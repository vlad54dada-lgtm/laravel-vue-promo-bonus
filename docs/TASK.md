# Тестове завдання: AI-асистований розробник (Laravel/Vue)

> Оригінал: `AI-Assisted Developer.pdf`. Текст збережено дослівно як джерело істини для перевірки повноти реалізації.

Завдання складається з двох частин: створення невеликого проєкту з використанням Claude Code (або іншого AI-інструменту для розробки) і рев'ю фрагмента коду. Домен продукту — гемблінг/беттинг-платформа: логіка стосується балансу гравця та бонусів, тому коректність і захист від зловживань (подвійне нарахування, від'ємні суми) важливі так само, як і те, що фіча просто працює.

## Умови виконання

- Усе виконується на вашому обладнанні, зі своїм доступом до AI-інструменту розробки — жодних матеріалів, доступів чи репозиторіїв від нас не потрібно.
- Стек: Laravel (бекенд, REST API) + Vue (фронтенд, звертається до API через axios).
- Результат публікується у вашому персональному Git-репозиторії (публічному або з наданим доступом), з реальною історією комітів, а не одним фінальним комітом.

## Частина 1. Створення міні-проєкту

Створіть Laravel-проєкт із REST API та Vue-фронтендом за наведеними нижче тікетами.

### Тікет 1 — Нарахування бонусу за промокодом

**Бекенд:**

`POST /api/promo/claim` — приймає код промокоду (обов'язково, формат: 6–12 символів, латинські літери й цифри). Гравець визначається з токена автентифікації, не з тіла запиту. Перевіряється, що код існує, не прострочений і ще не був використаний цим гравцем раніше. У разі успіху бонус нараховується на баланс гравця, у відповіді повертаються оновлений баланс і сума нарахованого бонусу. Некоректні дані (неправильний формат коду) повертають 422 з описом помилки; неіснуючий, прострочений або вже використаний код — окрему помилку з чітким поясненням причини.

`GET /api/promo/history` — повертає історію застосувань промокодів цим гравцем із пагінацією, з фільтром за статусом (успішно застосовано / відхилено).

**Фронтенд:** Форма введення промокоду з індикацією стану (завантаження/успіх/помилка з текстом причини). Під формою — список історії застосованих кодів із датою, сумою й статусом.

### Тікет 2 — Скасування помилково нарахованого бонусу

Виконується в тому самому проєкті, після Тікета 1.

**Бекенд:** `PATCH /api/promo/{claimId}/revoke` — скасовує раніше нараховане за промокодом бонусне нарахування і знімає відповідну суму з балансу гравця. Повторний виклик на вже скасованому нарахуванні повертає помилку, а не тихо списує кошти вдруге.

**Фронтенд:** Кнопка «Скасувати» напроти кожного застосованого промокоду в історії, з підтвердженням дії та оновленням статусу й балансу після скасування.

## Частина 2. Рев'ю коду

Нижче — фрагмент коду, який AI-інструмент згенерував за тікетом «нарахувати бонус на баланс гравця» в іншому проєкті. Розгляньте його так, як розглядали б PR колеги: без запуску, письмово вкажіть усе, що вас насторожує чи що ви б виправили.

```php
// routes/api.php
Route::get('/players/{player}/credit-bonus', [WalletController::class, 'creditBonus']);
```

```php
// app/Http/Controllers/WalletController.php
public function creditBonus(Request $request, Player $player)
{
    $player->balance += $request->amount;
    $player->save();

    return response()->json(['success' => true, 'balance' => $player->balance]);
}
```

```js
// resources/js/components/BonusCredit.vue (фрагмент методу)
async creditBonus(amount) {
  const response = await axios.get(`/api/players/${this.player.id}/credit-bonus`, {
    params: { amount }
  })
  this.player.balance = response.data.balance
}
```

## Що потрібно надіслати

1. Посилання на Git-репозиторій з проєктом із Частини 1.
2. Файл із логом промптів: що саме ви запитували в AI-інструменту на кожному тікеті, які були ітерації та виправлення.
3. Коротке відео (2–5 хв, будь-який інструмент запису екрана) або послідовність скріншотів, що показує запуск проєкту і роботу обох фіч.
4. Текстову відповідь по Частині 2 — рев'ю коду.
